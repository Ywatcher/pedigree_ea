# Viewer bundles: generate, share, and open

A viewer bundle contains the code and recorded data needed to inspect an existing search. Recipients do not need the full repository, original measurement files, or an EA run. ZIP assets can be downloaded from the repository's [Releases page](https://github.com/Ywatcher/pedigree_ea/releases) when published.

## Choose a bundle

| Bundle | Contents | Requirements |
|---|---|---|
| Standalone page | `index.html` with embedded data/code, plus `README.txt` | A modern browser; no Python |
| Full database viewer | SQLite run record, required Python modules and web assets, `requirements.txt`, and `README.txt` | Python 3.12+, NumPy, NetworkX >=3.5, and a modern browser |

The standalone page provides the exported animation panels and controls. The full viewer provides database exploration, including population history, progress charts, candidate details, per-pair predictions, and lineage. It does not require DEAP, Matplotlib, JupyterLab, or a separate SQLite server.

## Open a ZIP downloaded from a release

Download the desired viewer ZIP from the release's **Assets** list, rather than the automatically generated source-code archive. Extract the ZIP completely using your file manager. Each ZIP contains a named folder; enter that folder and consult its `README.txt`.

### Standalone page

Open the extracted folder's `index.html` in Firefox, Chrome, Edge, or another modern browser. Open the file after extraction, rather than inside the ZIP. No server or installation is needed.

For example, `task03-page.zip` extracts to `task03-page/index.html`.

### Full database viewer

Open a terminal in the extracted folder containing `requirements.txt` and `run.sqlite`. For a Task03 bundle named `task03-viewer`, run:

```bash
cd task03-viewer
python --version
python -m pip install -r requirements.txt
python scripts/visualize.py run.sqlite
```

Use Python 3.12 or newer. If your system calls it `python3` instead of `python`, substitute `python3` in these commands. On Windows, `py -3` can also select Python; check its version first. Install the dependencies with the same interpreter used to launch the viewer. The installation needs internet access unless the dependencies are already available locally.

Visit **http://127.0.0.1:8765** in your browser. Keep the terminal process running while exploring; press Ctrl+C in that terminal to stop it. This address serves the viewer on your own computer.

Select a run, move through generations, and click candidates to inspect their values and lineage. Use the **Explain** switch for the drawing legend and descriptions of the controls and objectives. Reference pedigrees are comparisons for analysis; they were not provided to the search.

If port 8765 is occupied:

```bash
python scripts/visualize.py run.sqlite --port 8766
```

Then open http://127.0.0.1:8766. If an import fails, rerun the dependency installation with the same Python interpreter. If files cannot be found, check that the ZIP was fully extracted and the terminal is in the folder containing `run.sqlite`.

## Generate a bundle

From the repository root, use [scripts/pack_viewer.py](../scripts/pack_viewer.py). The packaging script uses only Python's standard library; the recipient dependencies are listed inside database bundles.

### Full database viewer

Replace the input path with the run-record database you want to share:

```bash
python scripts/pack_viewer.py results/db/YOUR_RUN.sqlite --name my-viewer
```

This creates:

```text
viewer_bundles/
├── my-viewer/
│   ├── README.txt
│   ├── requirements.txt
│   ├── run.sqlite
│   ├── scripts/visualize.py
│   └── src/pedigree_ea/       required viewer modules and web assets
└── my-viewer.zip
```

The database is copied through SQLite's backup API to produce a consistent standalone snapshot. The bundle includes all runs and sample IDs in that database, along with stored inputs and references. The source bundle excludes search strategies, the EA engine, caches, tests, and unrelated results.

### Standalone page

Replace the input with the self-contained page generated by `scripts/animate.py`:

```bash
python scripts/pack_viewer.py plt/YOUR_PAGE.html --name my-page
```

This creates `viewer_bundles/my-page/` containing `index.html` and `README.txt`, plus `viewer_bundles/my-page.zip`.

Both folders and ZIPs are under the repository root and excluded from Git. Use `--no-zip` for a folder only. Omit `--name` to get a timestamped name. Existing bundles are not overwritten; choose another name when generating an updated release asset.

### Task03 examples

The following recorded files were used for the example bundles; they are generated local outputs and are not included in a fresh source checkout:

```bash
python scripts/pack_viewer.py results/db/anim_task3-500kb-kin_20261008-153321-246583.sqlite --name task03-viewer
python scripts/pack_viewer.py plt/anim_task3-500kb-kin_20261008-153321-246583.html --name task03-page
```

These examples compare Direct, Direct + POSS, NEAT-like, and CGP-like runs with about 20,000 evaluations per method. If `task03-viewer` or `task03-page` already exists, use a new name.

## Upload bundles with a release

Attach the generated `.zip` files from `viewer_bundles/` to your GitHub release as assets. The generated directories and ZIPs remain git-ignored; they do not need to be committed to the source repository.

In the release description, identify the dataset, included methods, evaluation budget, latent-person bound, and tolerances. Link this guide and explain which asset is the browser-only page and which is the full Python viewer. Recipients should follow the included `README.txt`, which travels with their bundle.
